概念頁

語言模型：預測下一個 token

LLM 的核心工作只有一件事：根據前文，算出下一個 token 的機率，然後一個接一個寫下去。

一句話

語言模型就是「給它前面的文字，它預測下一個詞」的模型 S3。大型語言模型（LLM）是同一件事的超大版本。

從手機鍵盤開始想

手機鍵盤的選字建議就是一個小型語言模型 S3。GPT-2 做的事原理相同，只是規模差很多：作者用的鍵盤 SwiftKey 約佔 78 MB，而最小的 GPT-2 光是參數就要約 500 MB S3。

用機率來說

一段文字的機率可以拆成一連串條件機率相乘：每個詞的機率都以它前面的詞為條件 S6。模型要學的，就是「在這段前文之後，每個可能的下一個 token 各有多少機率」。

一次只寫一個 token

GPT 這類模型是自回歸的：一次生成一個 token，把它接到輸入後面，再預測下一個 S3。輸出長度不是事先定好的，模型產生結束（EOS）token 時才停 S6；GPT-2 另外有 1,024 個 token 的上下文上限 S3。

Decoder-only 模型用同一套「預測下一個 token」的方式，也能做翻譯與摘要 S3。

實際挑哪一個 token 有很多做法，見 解碼策略：從機率到文字。

不需要人工標註

這類模型用自監督方式訓練：訓練目標直接從輸入文字自動算出，不需要人去標註 S4。常見的兩種目標：

  • Causal language modeling：根據前面的詞預測下一個詞，只能看過去 S4。GPT 類模型用這種。
  • Masked language modeling：預測句子中被遮住的詞，可以看左右兩側 S4。BERT 類模型用這種。

兩種目標對應到不同的模型家族，見 三大模型家族：BERT、GPT、T5；訓練流程見 預訓練與微調。

容易誤會的地方

  • 「模型是一次想好整句再輸出」：不是。每一步只決定一個 token，而且已經寫出的 token 不會回頭重算 S3。
  • 「token 就是一個字或一個詞」：不一定，token 常常是詞的一部分 S3，見 Token 與 BPE 斷詞。

概念頁

Token 與 BPE 斷詞

模型看不懂文字，只看得懂編號。BPE 從字元出發，反覆合併最常見的相鄰組合，學出一套子詞詞彙。

一句話

斷詞（tokenization）把文字切成 token。GPT-2 這類模型的 token 常常是詞的一部分，也就是「子詞」S3。「比字元大、比單字小」是本 Wiki 的白話說法。

為什麼不直接用單字

GPT-2 用 byte pair encoding（BPE）建立詞彙，所以它的 token 常常是詞的一部分而不是整個詞 S3。它的詞彙約 50,000 個 S3；原始 Transformer 論文的英德翻譯也用 BPE，共享詞彙約 37,000 個 token S1。子詞的效果在下面的玩具例子看得到：常見的字是一個 token，少見的字由幾個 token 拼成 S5。

BPE 怎麼學出詞彙

BPE 最初是文字壓縮演算法，後來 OpenAI 在預訓練 GPT 時把它拿來斷詞；GPT、GPT-2、RoBERTa、BART、DeBERTa 都使用它 S5。

訓練步驟 S5：

  • 把語料切成單字並計算次數，再把每個單字拆成單一符號。
  • 統計所有相鄰符號對的出現次數。
  • 把最常出現的一對合併成一個新 token，加入詞彙。
  • 重複統計與合併，直到詞彙達到想要的大小。

每次合併都記成一條規則，之後對新文字斷詞時依同樣順序套用 S5。

玩具例子

語料：hug 出現 10 次、pug 5 次、pun 12 次、bun 4 次、hugs 5 次 S5。基礎詞彙是 7 個符號 b、g、h、n、p、s、u S5。

  • 第 1 次合併：(u, g) 出現 20 次，比 (h, u) 的 15 次多，所以 u + g → ug S5。
  • 第 2 次合併：(u, n) 出現 16 次，u + n → un S5。
  • 第 3 次合併：(h, ug) 出現 15 次，h + ug → hug S5。

3 次合併後，詞彙變成 10 個 token S5。常見的 hug 變成一個 token，較少見的 pug 則是 p 加 ug 兩個 token。

遇到沒看過的字元

用上面的規則斷 bug 會得到 [b, ug]；斷 mug 會得到 [UNK, ug]，因為 m 不在基礎詞彙裡 S5。

GPT-2 與 RoBERTa 改用 byte-level BPE 避開這個問題：把文字看成 byte，基礎詞彙只有 256 個，任何字元都能表示，不會出現未知 token S5。

容易誤會的地方

  • 玩具例子的 [UNK] 是字元層級 BPE 的現象，不是 GPT-2 的行為；兩者在來源中是分開講的 S5。
  • 許多圖解文章為了好懂把「詞」和 token 混用，讀的時候要自己換算，見 來源之間的不一致與未解問題。

概念頁

Embedding 與位置編碼

每個 token 先查表變成一個向量，再加上代表位置的向量，模型才同時知道「是什麼字」與「在第幾個」。

一句話

Embedding 把 token 編號換成向量 S3；位置編碼把「順序」這個資訊加進向量裡 S2。兩者相加後才送進第一個區塊 S3。

Embedding：查表

模型有一張 token embedding 矩陣，每一列對應一個詞彙；輸入的每個 token 都到這張表查出自己的向量 S3。原始 Transformer 的向量是 512 維 S1S2，最小的 GPT-2 是 768 維 S3。

只有最底層收到 embedding，往上每一層收到的是下一層的輸出 S2。

為什麼還需要位置

自注意力本身不知道詞序 S2。原始論文拿掉了遞迴與卷積，所以必須另外把位置資訊加到輸入 embedding 上 S1。

沒有位置資訊的話，模型看到的只是一袋 token，分不出「狗咬人」與「人咬狗」。這個比喻是本 Wiki 為了教學加的，不是來源原文。

怎麼加

  • 原始論文：用不同頻率的 sin 與 cos 函數算出位置向量，直接加到 embedding 上；作者也試過讓模型自己學位置 embedding，結果幾乎相同 S1。
  • GPT-2：有一張位置編碼矩陣，為 1,024 個位置各存一個向量，加到 token embedding 上 S3。

同一張表用兩次

原始論文讓輸入 embedding、輸出 embedding 與 softmax 前的線性層共用同一個權重矩陣 S1。GPT-2 也類似：最上層輸出的向量乘上 embedding 矩陣，就得到每個詞彙的分數 S3。這些分數怎麼變成字，見 解碼策略：從機率到文字。

容易誤會的地方

  • 圖解文章裡位置編碼的圖是 sin、cos 各半串接，論文是交錯排列，兩者圖案看起來不同 S2，見 來源之間的不一致與未解問題。

概念頁

為什麼 Transformer 取代了 RNN

RNN 必須一個字一個字依序算，慢又難記住遠處的字；注意力讓所有位置直接相連，可以平行訓練。

一句話

Transformer 拿掉了遞迴與卷積，只靠注意力，讓任意兩個位置只需常數次運算就能相連，而且整個序列可以平行處理 S1。

之前的模型卡在哪裡

  • RNN（LSTM、GRU）必須依序處理 token，單一訓練樣本內無法平行運算，序列越長成本越高 S1。
  • 以 CNN 為基礎的模型比較能平行，但關聯兩個位置所需的運算數會隨距離增加，遠距離的依賴較難學 S1。

論文的比較

依論文表 1 S1：

層的種類 每層複雜度 必須依序做的運算 兩位置間最長路徑
自注意力 O(n²·d) O(1) O(1)
遞迴層 O(n·d²) O(n) O(n)

n 是序列長度，d 是表示維度。當 n 小於 d 時（句子層級常見），自注意力每層比遞迴層快 S1。

代價也看得出來：自注意力的成本隨長度平方成長，所以序列很長時並不便宜 S1。

實驗結果

  • 硬體是一台裝有 8 顆 GPU 的機器；base 模型訓練約 12 小時，big 模型約 3.5 天 S1。
  • Big 模型英德翻譯 BLEU 為 28.4，比先前最佳結果高出超過 2 BLEU S1。
  • Big 模型英法翻譯 BLEU 為 41.8 S1。這個數字在來源內有兩種寫法，見 來源之間的不一致與未解問題。

容易誤會的地方

  • 「Transformer 計算量一定比 RNN 小」：不對。它的優勢是能平行、路徑短；每層成本在長序列下反而成長更快 S1。

概念頁

自注意力（Self-Attention）

處理每個 token 時，讓它去「看」句子裡其他 token，依相關程度加權後混合進自己的表示。

一句話

自注意力讓模型在處理每個詞的表示時，特別關注句中某些詞、忽略其他詞 S4。它是 Transformer 的核心。

直覺：it 指的是誰

例句：「The animal didn't cross the street because it was too tired.」it 指的是 animal 還是 street？自注意力讓模型在編碼 it 時去看其他位置，把 it 和 animal 關聯起來 S2。

另一個例子：把「You like this course」翻成法文，翻 like 需要注意 You，因為法文動詞變化取決於主詞；翻 this 需要注意 course，因為用字隨名詞陰陽性改變 S4。

怎麼算

每個 token 會產生三個向量：Query（我想找什麼）、Key（我是什麼）、Value（我能提供什麼）。括號裡的白話是本 Wiki 的教學說法；來源的定義是「embedding 乘上三個訓練出的權重矩陣」S2。

圖解文章把計算分成 6 步 S2：

  • 從每個 embedding 算出 query、key、value 三個向量。原始模型中它們是 64 維，比 512 維的 embedding 小 S2。
  • 用目前這個 token 的 query 與每個 token 的 key 做內積，得到分數 S2。
  • 把分數除以 8，也就是 key 維度 64 的平方根 S2。
  • 做 softmax，讓分數都為正且總和為 1 S2。
  • 每個 value 乘上自己的分數，不相關的 token 被縮到接近零 S2。
  • 把加權後的 value 加總，得到這個位置的輸出 S2。

寫成一條公式是 softmax(QKᵀ / √d_k) · V S1。除以 √d_k 是因為維度大時內積會變大，softmax 會落在梯度極小的區域，不好訓練 S1。

遮罩：不准偷看未來

生成文字時，模型不能看到還沒寫出來的字。做法是在 softmax 之前把未來位置的分數設成負無限大，權重就變成零 S2S3。這種版本叫遮罩自注意力，是 decoder 與 GPT 類模型使用的 S1S3。

Encoder 的自注意力沒有遮罩，可以看整句 S4。

為什麼它適合長句子

自注意力讓任意兩個位置之間的路徑長度是常數；遞迴層則要一步步傳遞，路徑長度隨序列長度成長 S1。完整比較見 為什麼 Transformer 取代了 RNN。

容易誤會的地方

  • 注意力權重不是人寫的規則，而是由訓練出來的 Q/K/V 權重矩陣算出的 S2。
  • 一層自注意力只算一種「誰看誰」的關係不夠用，實際模型同時算好幾組，見 多頭注意力（Multi-Head Attention）。

概念頁

多頭注意力（Multi-Head Attention）

同時跑好幾組各自獨立的自注意力，每一組關注不同的關係，最後把結果接起來。

一句話

多頭注意力就是把 自注意力（Self-Attention） 平行做很多份，每一份（一個「頭」）有自己的 Q/K/V 權重矩陣 S2。

為什麼要很多頭

兩個好處：模型能同時關注不同的位置，並且擁有多個表示子空間 S1S2。

在 it 的例子裡，編碼 it 時一個頭主要關注 the animal，另一個頭關注 tired S2。一句話裡同時存在「指代誰」和「狀態是什麼」這些不同的關係，多頭讓它們可以分開處理。

數字

  • 原始 Transformer 用 8 個頭，每個頭的向量是 64 維，也就是 512 除以 8 S1。
  • 因為每個頭的維度變小，總計算量和單頭全維度的注意力相近 S1。
  • 論文的 big 模型用 16 個頭 S1；最小的 GPT-2 用 12 個頭 S3。

怎麼合起來

每個頭各自產生一個輸出，全部串接起來，再乘上一個額外的權重矩陣投影回模型維度，交給後面的前饋網路 S1S2。

在原始 Transformer 裡出現的三個地方

依論文的說明 S1：

  • Encoder 自注意力：每個位置可以看前一層的所有位置。
  • Decoder 遮罩自注意力：每個位置只能看目前與之前的位置。
  • Encoder-decoder 注意力：query 來自 decoder，key 與 value 來自 encoder 的輸出，讓 decoder 每一步都能看整個輸入句子。

GPT-2 的 decoder-only 區塊拿掉了看 encoder 的那一層，所以只剩第二種 S3，見 三大模型家族：BERT、GPT、T5。

概念頁

Transformer 架構全貌

原始 Transformer 是 encoder 堆疊加 decoder 堆疊；每一層都是「注意力 + 前饋網路」，外面包殘差連接與正規化。

一句話

把一個「注意力加前饋網路」的區塊重複堆很多層，就是 Transformer。原始版本有 encoder 與 decoder 兩疊，用來做翻譯 S2。

兩疊各 6 層

原始模型的 encoder 與 decoder 各由 6 層相同結構的層堆成 S1S2。各層結構相同，但權重不共用 S2。6 不是唯一可行的數字 S2。

每一層裡面有什麼

  • Encoder 層有 2 個子層：多頭自注意力、前饋網路 S1。
  • Decoder 層有 3 個子層：遮罩自注意力、看 encoder 輸出的 encoder-decoder 注意力、前饋網路 S1。
  • 每個子層外面都包一條殘差連接，之後接 layer normalization S1S2。

前饋網路對每個位置獨立套用，內層維度是 2048，輸入輸出是 512 S1。各個 token 只在自注意力層彼此相依，所以前饋網路可以對所有位置平行計算 S2。

資料怎麼流過去

以翻譯為例，依圖解文章的順序 S2：

  • 輸入句子的每個 token 變成 embedding，加上位置編碼（見 Embedding 與位置編碼）。
  • 向量一層層流過 encoder 堆疊。
  • 最上層 encoder 的輸出轉成一組 K、V 向量，提供給每一層 decoder 的 encoder-decoder 注意力使用。
  • Decoder 一步輸出一個 token，再把它餵回最底層，直到出現結束符號。
  • Decoder 最上層輸出的向量經過線性層變成 logits（每個詞彙一個分數），再經 softmax 變成機率。

最後一步怎麼從機率挑出字，見 解碼策略：從機率到文字。

規模

論文的 base 模型約 6,500 萬參數，big 模型約 2.13 億參數 S1。和後來的模型相比很小，各家族的發展見 三大模型家族：BERT、GPT、T5。

容易誤會的地方

  • 「Transformer 一定有 encoder 和 decoder」：原始版本是，但後來的 BERT 只用 encoder、GPT 只用 decoder，見 三大模型家族：BERT、GPT、T5。

只用 encoder 的擅長理解，只用 decoder 的擅長生成，兩者都用的擅長「讀一段、寫一段」。GPT 系列屬於 decoder-only。

一句話

原始 Transformer 之後，模型分成三條路線：encoder-only、decoder-only、encoder-decoder S4。

三個家族

依課程的分類整理 S4：

家族 代表 怎麼看上下文 適合的任務
Encoder-only（自編碼） BERT 左右兩側都看 句子分類、命名實體辨識等理解型任務
Decoder-only（自回歸） GPT 只看前文 文字生成
Encoder-decoder（sequence-to-sequence） T5 讀完整輸入，再逐步生成 翻譯、摘要

區塊長得哪裡不一樣

依圖解 GPT-2 的說明 S3：

遮住資訊的方式也不同：BERT 把輸入的詞換成 [mask]；GPT-2 是在注意力計算裡擋掉未來的位置 S3。

GPT-2 的規格

  • 訓練資料 WebText 約 40 GB，是從網路爬下來的文字 S3。
  • 最小的版本 embedding 為 768 維、12 個注意力頭 S3。
  • 詞彙約 50,000 個，上下文最多 1,024 個 token S3。

概念頁

預訓練與微調

先用海量文字讓模型學會語言（預訓練），再用少量任務資料調整（微調）。前者昂貴，後者便宜。

一句話

預訓練讓模型從大量原始文字學到語言的統計規律；微調再把這個通用模型調整到特定任務上 S4。

訓練一步在做什麼

模型對一段輸入算出「下一個 token 的機率分布」，再和正確答案比較；正解用 one-hot 向量表示 S2。一開始輸出是亂的，反向傳播一點一點調整權重，讓輸出分布靠近正解 S2。

正確答案不用人標，直接來自文字本身，這就是自監督 S4，見 語言模型：預測下一個 token。

預訓練

從隨機初始化的權重開始，在非常大的資料上從頭訓練，可能要好幾週 S4。例如 GPT-2 的訓練資料約 40 GB 的網路文字 S3。

一般而言，更好的表現來自更大的模型與更多的資料；訓練大模型耗時、耗算力，也有可觀的環境成本 S4。

微調

拿預訓練好的模型，在較小、任務專屬、有人工標註的資料上繼續訓練 S4。預訓練學到的知識轉移到新任務上，稱為遷移學習 S4。

微調比從頭訓練划算的原因 S4：

  • 預訓練模型已經具備與目標任務相通的語言知識。
  • 需要的資料少得多。
  • 花的時間與資源較少。
  • 效果通常比從頭訓練好。

一個實例：有研究先以語言模型的方式預訓練 decoder-only 模型，再微調做摘要，在資料有限時勝過預訓練的 encoder-decoder S3。

分享權重

分享訓練好的權重、在別人的模型上繼續做，可以降低整個社群的算力成本與碳足跡 S4。這也是為什麼會區分 architecture 與 checkpoint，見 三大模型家族：BERT、GPT、T5。

不一定要微調

GPT-3 這類更大的模型不需微調就能做許多任務（zero-shot）S4。

解碼策略：從機率到文字

模型只給出每個 token 的機率，「怎麼挑」是另一個決定。Greedy 穩但呆板，抽樣加上 temperature、top-k、top-p 才有變化。

一句話

模型最上層輸出的向量經線性層變成 logits，softmax 再把它變成每個詞彙的機率 S2。解碼策略決定如何從這個機率分布挑出下一個 token。

Greedy：永遠選最高的

每一步都選機率最高的那一個 S2S6。快又簡單，但可能錯過整體更好的序列，而且容易開始重複同樣的片語 S6。把 top-k 設成 1 就等於 greedy，同樣容易陷入重複迴圈 S3。

Beam search：多留幾條路

每一步保留機率最高的幾條部分序列，最後回傳整體機率最高的一條 S6。原始 Transformer 論文做翻譯時用的 beam size 是 4 S1。

它適合輸出長度大致可預測的任務，例如翻譯與摘要；對話、故事這類開放式生成比較不適合 S6。理由之一：人寫的文字並不總是選高機率的下一個詞，beam search 產生的文字太好預測 S6。

抽樣：照機率擲骰子

依機率分布隨機抽出下一個 token，所以每次結果不同；結果更多樣，但可能不連貫 S6。下面三個旋鈕用來控制抽樣：

Temperature

在抽樣前重新縮放分布。調低會讓分布更尖，高機率的更容易被選、低機率的更不容易 S6。來源示範中設為 0.6 時文字較連貫；趨近 0 時行為等同 greedy S6。

Top-k

只保留機率最高的 K 個候選，重新正規化後再抽樣 S6。GPT-2 採用這個方法 S6，圖解文章舉 40 當例子 S3，部落格示範用 50 S6。缺點是 K 固定，不會隨分布形狀調整 S6。

Top-p（nucleus）

選出累積機率剛好達到門檻 p 的最小一組候選，再從中抽樣 S6。候選數量會自動變化：示範中 p 為 0.92 時，第一步需要 9 個詞，第二步只需要 3 個 S6。Top-k 與 top-p 可以一起用 S6。

該用哪一種

對開放式生成，top-p 與 top-k 抽樣通常比 greedy 與 beam search 產生更流暢的文字；但沒有一種方法適合所有情況 S6。

容易誤會的地方

  • 「同一個問題每次答案不同，代表模型不穩定」：不是，那是抽樣造成的，模型算出的機率分布是一樣的 S6。
  • 「Temperature 越高越有創意」只說對一半：分布變平之後，不連貫的機會也變高 S6。

S1｜Attention Is All You Need

2017 年提出 Transformer 的原始論文，是架構、公式與實驗數字的第一手來源。

論文 · Vaswani 等 8 位作者 · 2017-06-12 · 原文連結

這篇在講什麼

提出 Transformer：一個完全不使用遞迴（RNN）與卷積（CNN）、只靠注意力機制的序列轉換模型，並在英德、英法機器翻譯上取得當時最佳成績，而且訓練更快。

重點事實

動機

  • RNN（LSTM、GRU）必須依序處理 token，單一訓練樣本內無法平行運算，序列越長成本越高。
  • 以 CNN 為基礎的模型比較能平行，但要關聯兩個位置所需的運算數會隨距離增加，遠距離依賴較難學。
  • Transformer 完全拿掉遞迴與卷積，任意兩個位置之間只需常數次運算就能相連。

架構

  • Encoder 與 decoder 各由 6 層相同的層堆疊而成，模型維度 d_model 為 512。
  • Encoder 每層有 2 個子層：多頭自注意力、逐位置的前饋網路。
  • Decoder 每層有 3 個子層：遮罩自注意力、對 encoder 輸出的 encoder-decoder 注意力、前饋網路。
  • 每個子層外都包一條殘差連接，之後接 layer normalization。
  • Decoder 的自注意力會被遮罩，讓每個位置看不到後面的位置；再加上輸出向右位移一格，確保生成是自回歸的。

注意力

  • Scaled dot-product attention 的公式是 softmax(QKᵀ / √d_k) · V。
  • 除以 √d_k 的理由：d_k 很大時內積數值會變大，把 softmax 推到梯度極小的區域。
  • 多頭注意力使用 8 個平行的頭，每個頭把 query、key、value 投影到 64 維（512 除以 8）。各頭輸出串接後再投影一次，總計算量與單頭全維度相近。
  • 多頭讓模型能同時從不同的表示子空間、不同位置擷取資訊。
  • 多頭注意力在模型中有三種用法：encoder 自注意力（每個位置看前一層所有位置）、decoder 遮罩自注意力（只看目前與之前的位置）、encoder-decoder 注意力（query 來自 decoder，key 與 value 來自 encoder 輸出）。

其他元件

  • 前饋網路對每個位置獨立套用，內層維度 2048，輸入輸出維度 512。
  • 輸入與輸出的 embedding 層，以及 softmax 前的線性層，共用同一個權重矩陣。
  • 因為沒有遞迴與卷積，必須把位置資訊加到輸入 embedding 上。論文用不同頻率的 sin 與 cos 函數；作者也試過用學習的位置 embedding，結果幾乎相同。

為什麼用自注意力（論文表 1）

  • 自注意力：每層複雜度 O(n²·d)，序列運算 O(1)，最長路徑 O(1)。
  • 遞迴層：每層複雜度 O(n·d²)，序列運算 O(n)，最長路徑 O(n)。
  • 當序列長度 n 小於表示維度 d 時（句子層級常見），自注意力每層比遞迴層快。

訓練與結果

  • 英德資料約 450 萬句對，用 BPE，共享詞彙約 37,000 個 token。英法資料 3,600 萬句，詞彙 32,000。
  • 硬體是一台裝有 8 顆 NVIDIA P100 GPU 的機器。Base 模型訓練 100,000 步約 12 小時；big 模型訓練 300,000 步約 3.5 天。
  • 學習率先線性暖身 4,000 步再衰減。Base 模型 dropout 為 0.1，label smoothing 為 0.1。
  • Base 模型約 6,500 萬參數，英德 BLEU 27.3、英法 BLEU 38.1。
  • Big 模型約 2.13 億參數、16 個頭，英德 BLEU 28.4、英法 BLEU 41.8。Big 模型在英德上比先前最佳結果（含 ensemble）高出超過 2 BLEU。
  • 推論時使用 beam search，beam size 為 4。

Jay Alammar 的圖解文章，用翻譯例子一步步拆解原始 Transformer，是直覺與例子的主要來源。

部落格文章 · Jay Alammar · 2018-06-27 · 原文連結

這篇在講什麼

把原始 Transformer 當成一個「輸入一句話、輸出翻譯」的黑盒子，再逐層打開：encoder 堆疊、decoder 堆疊、自注意力的逐步計算、多頭、位置編碼、最後的線性層與 softmax，以及訓練時怎麼比較輸出與正解。

重點事實

整體結構

  • 模型內部是一個編碼元件與一個解碼元件，各是 6 個 encoder、6 個 decoder 的堆疊；文章提到 6 不是唯一可行的數字。
  • 所有 encoder 結構相同但權重不共用。每個 encoder 有自注意力與前饋網路兩個子層；decoder 在兩者之間多一層 encoder-decoder 注意力。
  • 每個輸入詞先變成 512 維的 embedding。只有最底層 encoder 收到 embedding，其上各層收到下一層的輸出。
  • 各個詞在 encoder 中走各自的路徑，只有在自注意力層彼此相依，所以前饋網路可以對各位置平行計算。

自注意力的直覺

  • 例句：「The animal didn't cross the street because it was too tired.」it 指的是 animal 還是 street？自注意力讓模型在編碼 it 時去看其他位置，把 it 與 animal 關聯起來。

逐步計算（文章分成 6 步）

  • 第 1 步：每個 embedding 乘上訓練出的權重矩陣，得到 Query、Key、Value 三個向量，維度是 64，比 512 維的 embedding 小。
  • 第 2 步：用目前這個詞的 query 與每個詞的 key 做內積，得到分數。
  • 第 3、4 步：把分數除以 8（key 維度 64 的平方根）讓梯度更穩定，再做 softmax，使分數為正且總和為 1。
  • 第 5 步：每個 value 向量乘上自己的 softmax 分數，不相關的詞會被縮到接近零。
  • 第 6 步：把加權後的 value 向量加總，就是這個位置的自注意力輸出。
  • 矩陣形式：把所有 embedding 疊成矩陣 X，第 2 到第 6 步可以濃縮成一條公式。

多頭注意力

  • 文章用 8 個頭，每個頭有各自隨機初始化的 Q/K/V 權重矩陣。
  • 兩個好處：模型能關注不同位置；擁有多個表示子空間。
  • 8 個頭各產生一個輸出矩陣，串接後再乘上一個額外的權重矩陣，變成前饋層能接受的單一矩陣。
  • 例子中編碼 it 時，一個頭主要關注 the animal，另一個頭關注 tired。

位置編碼、殘差

  • 自注意力本身不知道詞序，所以在每個輸入 embedding 上加一個位置編碼向量。
  • 文章圖示的 Tensor2Tensor 實作把 sin 與 cos 各放一半再串接；論文的做法是交錯排列。文章在 2020 年 7 月的更新中說明了這個差別。
  • 每個子層外都有殘差連接，之後接 layer normalization；decoder 也一樣。

Decoder 與輸出

  • 最上層 encoder 的輸出會轉成一組 K、V 注意力向量，供每個 decoder 的 encoder-decoder 注意力層使用。
  • 解碼是逐步的：每一步輸出一個元素，再把它餵回最底層 decoder，直到出現結束符號。
  • Decoder 的自注意力只能看較早的位置；未來位置在 softmax 前被設為負無限大。
  • Decoder 堆疊輸出一個向量，線性層把它投影成 logits 向量，每個詞彙一格（文中例子是 10,000 個英文詞），softmax 再轉成機率，機率最高的詞被選為這一步的輸出。

訓練

  • 訓練時走同樣的前向流程，但把輸出與標註的正確答案比較。正解用 one-hot 向量表示。
  • 一開始輸出分布是亂的，反向傳播調整權重讓它靠近目標；比較兩個分布可參考 cross-entropy 與 KL divergence。
  • 實際的詞彙量大約 30,000 到 50,000。
  • Greedy decoding 每一步只留機率最高的詞；beam search 同時保留多個候選（文中例子 beam size 為 2）。

Jay Alammar 圖解 GPT-2，說明 decoder-only 模型如何一次生成一個 token，是「LLM 怎麼寫字」的主要來源。

部落格文章 · Jay Alammar · 2019 · 原文連結

這篇在講什麼

接續 S2，把焦點從翻譯用的 encoder-decoder 移到只用 decoder 區塊的 GPT-2：什麼是語言模型、GPT-2 與 BERT 的差別、遮罩自注意力，以及 token 如何一路流過堆疊變成下一個字的分數。

重點事實

語言模型

  • 語言模型做的事是：給定前面的文字，預測下一個詞。手機鍵盤的選字建議就是日常例子。
  • GPT-2 原理相同，但大得多。作者使用的鍵盤 SwiftKey 約佔 78 MB，最小的 GPT-2 光參數就要約 500 MB。

GPT-2 的規模

  • 訓練資料是 WebText，OpenAI 研究人員從網路爬下來約 40 GB 的文字。
  • 最小的模型每個 token 的 embedding 是 768 維，有 12 個注意力頭。
  • 詞彙約 50,000 個，可處理最多 1,024 個 token 的上下文。
  • 最大的版本約是最小版本的 13 倍大。
  • 作者從程式碼數出約 1.24 億參數，官方數字是 1.17 億，他不確定差異原因。

三種區塊

  • Encoder 區塊（原始 Transformer）：自注意力加前饋網路。
  • Decoder 區塊（原始 Transformer）：多一層去看 encoder 輸出的注意力；自注意力有遮罩，看不到未來的 token。
  • Decoder-only 區塊（GPT-2 使用）：拿掉看 encoder 的那一層，只剩遮罩自注意力與前饋網路。

BERT 與 GPT-2

  • BERT 用 encoder 區塊，GPT-2 用 decoder 區塊。
  • GPT-2 是自回歸的：一次生成一個 token，新 token 接到輸入後面再跑下一步。BERT 不是。
  • 取捨：BERT 放棄自回歸，換來能同時使用一個詞左右兩側的上下文。
  • BERT 把詞換成 [mask] 來遮住；GPT-2 則是在注意力計算裡擋掉未來位置。

生成流程

  • 從起始 token 開始，流過所有區塊得到一個向量，再對整個詞彙打分數。選出的 token 接回輸入，重複這個過程。
  • 已經處理過的 token，其表示不會因為後來新增的 token 而重算。
  • 生成到 1,024 個 token 上限或出現結束 token 時停止。
  • top-k 設為 1 就是永遠選分數最高的詞，容易陷入重複迴圈；文章舉 top-k 為 40 當折衷，從分數最高的 40 個詞中依分數抽樣。

Embedding 與位置

  • 模型在 token embedding 矩陣中查出每個輸入 token 的向量，矩陣每一列對應一個詞彙。
  • 位置編碼矩陣為 1,024 個位置各提供一個向量，加到 token embedding 上，讓模型知道順序。

遮罩自注意力與堆疊

  • 自注意力三步驟：建立 query、key、value；用 query 對各 key 打分；依分數加總 value。
  • 遮罩版只差在打分那一步：未來 token 的分數在 softmax 前被設成極大的負數，權重變成零。
  • 每個區塊先做遮罩自注意力再做前饋網路；前饋網路先擴張到模型維度的 4 倍（小模型為 3,072）再投影回來。
  • 每個區塊有自己的權重，但 embedding 矩陣全模型共用。最上層輸出的向量乘上 embedding 矩陣，得到每個詞彙的分數。

其他

  • GPT-2 用 byte pair encoding 建立詞彙，所以 token 常常是詞的一部分而不是整個詞。
  • Decoder-only 架構也用在翻譯、摘要、音樂生成。有研究先以語言模型預訓練 decoder-only 模型，再微調做摘要，在資料有限時勝過預訓練的 encoder-decoder。

Hugging Face 課程第 1 章第 4 節，提供模型家族、預訓練與微調、名詞定義等全景觀念。

線上課程 · Hugging Face · 持續更新（2026-11-17 讀取） · 原文連結

這篇在講什麼

用不含數學的方式介紹 Transformer 模型的歷史、三大家族、它們都是以自監督方式訓練的語言模型、預訓練與微調的關係，以及 encoder、decoder、注意力層各自的角色。

重點事實

時間軸（課程列出的代表性模型）

  • 2017 年 6 月：Transformer 架構問世，原始研究聚焦在翻譯。
  • 2018 年 6 月：GPT，第一個預訓練的 Transformer 模型。
  • 2018 年 10 月：BERT，為了產生更好的句子表示而設計的大型預訓練模型。
  • 2019 年 2 月：GPT-2，更大更好的 GPT，完整版一開始因倫理顧慮沒有公開。
  • 2019 年 10 月：T5，多任務的 sequence-to-sequence Transformer。
  • 2020 年 5 月：GPT-3，更大的 GPT-2，不需微調就能做許多任務（zero-shot）。
  • 2022 年 1 月：InstructGPT，訓練成更能遵循指令的 GPT-3。
  • 2023 年 1 月：Llama。2023 年 3 月：Mistral。2024 年 5 月：Gemma 2。2024 年 11 月：SmolLM2，給行動與邊緣裝置用的小模型。
  • 課程說明這份清單只是舉例，並不完整。

三大家族

  • GPT 類（自回歸）：根據前文一次生成一個 token。
  • BERT 類（自編碼）：建立對輸入文字的理解，通常用遮住詞的方式訓練。
  • T5 類（sequence-to-sequence）：把一個輸入序列對應到一個輸出序列。

都是語言模型

  • 上述模型都是在大量原始文字上訓練的語言模型，訓練方式是自監督：訓練目標由輸入自動算出，不需要人工標註。
  • 這樣的模型學到語言的統計規律，但要經過調整才對特定任務有用。
  • Causal language modeling：根據前面的詞預測下一個詞，輸出只依賴過去與現在。
  • Masked language modeling：預測句中被遮住的詞，可以用到兩側的上下文。

模型很大

  • 一般而言，更好的表現來自更大的模型與更多的資料。訓練大模型耗時、耗算力，也有可觀的環境成本；分享訓練好的權重能降低整個社群的成本與碳足跡。

預訓練、微調、遷移學習

  • 預訓練：從隨機初始化的權重開始，在非常大的資料上從頭訓練，可能要好幾週。
  • 微調：拿預訓練好的模型，在較小、任務專屬、有人工標註的資料上繼續訓練。
  • 遷移學習：預訓練學到的知識轉移到新任務上。
  • 微調比較划算的原因：預訓練模型已具備與目標任務相通的語言知識；需要的資料少得多；時間與資源較少；通常比從頭訓練效果好。

架構角色

  • Encoder：接收輸入並建立它的表示，重在理解。
  • Decoder：利用 encoder 的表示與其他輸入來生成目標序列，重在生成。
  • Encoder-only 適合理解型任務（句子分類、命名實體辨識）；decoder-only 適合生成型任務（文字生成）；encoder-decoder 適合需要輸入的生成任務（翻譯、摘要）。

注意力層

  • 注意力層讓模型在處理每個詞的表示時，特別關注句中某些詞、忽略其他詞。
  • 例子：把「You like this course」翻成法文時，翻 like 需要注意 You（法文動詞變化取決於主詞）；翻 this 需要注意 course（法文用字隨名詞陰陽性改變）。
  • 原始架構中，encoder 的注意力可以看整句；decoder 只能看已經生成的詞。訓練時為了效率把整個目標句餵給 decoder，但遮住未來的詞。

名詞

  • Architecture：模型的骨架，定義每一層與每個運算，例如 BERT。
  • Checkpoint：載入某個架構的一組訓練好的權重，例如 bert-base-cased。
  • Model：泛稱，兩者都可以指。

Hugging Face 課程第 6 章第 5 節，用玩具語料示範 BPE 如何學出子詞詞彙。

線上課程 · Hugging Face · 持續更新（2026-11-17 讀取） · 原文連結

這篇在講什麼

說明 BPE 斷詞演算法的來源、訓練步驟，並用一個五個單字的玩具語料完整走一遍合併過程，最後說明新文字如何套用學到的合併規則。

重點事實

來源與使用

  • BPE 最初是文字壓縮演算法，後來 OpenAI 在預訓練 GPT 時把它用於斷詞。
  • 使用 BPE 的模型包括 GPT、GPT-2、RoBERTa、BART、DeBERTa。

訓練步驟

  • 先正規化、預先切成單字，計算每個單字出現次數。
  • 建立基礎詞彙：寫出這些單字所用到的所有符號。
  • 把每個單字拆成單一符號的序列。
  • 統計所有相鄰符號對的出現次數（依單字頻率加權）。
  • 把最常出現的一對合併成新 token，加入詞彙，並取代語料中所有出現處。
  • 重複統計與合併，直到詞彙達到目標大小。每次合併都存成一條規則，之後依學到的順序套用。

玩具例子

  • 語料與次數：hug 出現 10 次、pug 5 次、pun 12 次、bun 4 次、hugs 5 次。
  • 基礎詞彙有 7 個符號：b、g、h、n、p、s、u。
  • 一開始 (h, u) 出現 15 次，但 (u, g) 出現 20 次（來自 hug、pug、hugs），所以第 1 次合併是 u + g → ug。
  • 第 2 次合併：(u, n) 出現 16 次，成為最常見的一對，u + n → un。
  • 第 3 次合併：(h, ug) 出現 15 次，h + ug → hug。
  • 3 次合併後詞彙共 10 個 token：b、g、h、n、p、s、u、ug、un、hug。

Byte-level BPE

  • GPT-2 與 RoBERTa 的 tokenizer 把文字看成 byte 而不是 Unicode 字元，基礎詞彙只有 256 個（每種 byte 一個），任何字元都能表示，不會出現未知 token。

對新文字斷詞

  • 正規化、切成單字、拆成字元，再依學到的順序套用合併規則。
  • 用上面 3 條規則：bug 會變成 [b, ug]；mug 會變成 [UNK, ug]，因為 m 不在基礎詞彙中；thug 會變成 [UNK, hug]。

介紹 greedy、beam search、抽樣、temperature、top-k、top-p 等解碼方法與各自的優缺點。

部落格文章 · Hugging Face · 2020-03-01（2023-07 更新） · 原文連結

這篇在講什麼

模型算出下一個詞的機率之後，「怎麼挑」會大幅影響生成的文字。這篇用 GPT-2 示範幾種主流解碼方法，並比較它們適合的情境。

重點事實

自回歸生成

  • 一個詞序列的機率被建模成一連串條件機率的乘積：每個詞的機率都以前面的詞為條件。
  • 輸出長度不是事先固定的，模型產生結束（EOS）token 時停止。

Greedy search

  • 每一步都選機率最高的那個詞。快又簡單，但可能錯過「先選一個機率普通的詞、後面接高機率詞」的更好序列。
  • 在 GPT-2 示範中，輸出一開始合理，之後開始重複同樣的片語。

Beam search

  • 每一步保留機率最高的幾條部分序列（num_beams 條），最後回傳整體機率最高的一條。
  • 缺點：輸出仍然容易重複；可以加 n-gram 懲罰來減少重複，但要小心它會擋掉合理的重複（例如城市名）。
  • 適合輸出長度大致可預測的任務，例如機器翻譯與摘要；對話、故事這類開放式生成比較不適合。
  • 一個論點是：人寫的文字並不總是選高機率的下一個詞，人想看的是有點意外的文字，而 beam search 產生的文字太好預測。

抽樣（sampling）

  • 依照條件機率分布隨機抽出下一個詞，所以每次執行結果不同（除非固定隨機種子）。
  • 結果更多樣，但可能不連貫。

Temperature

  • Temperature 會在抽樣前重新縮放 softmax 分布。調低會讓分布更尖：高機率的詞更可能被選，低機率的詞更不可能。
  • 示範中 temperature 設為 0.6 時文字較連貫。Temperature 趨近 0 時，抽樣的行為就等同 greedy search。

Top-K 抽樣

  • 只保留機率最高的 K 個詞，把機率重新正規化後再抽樣。GPT-2 採用這個方法。示範用的 K 是 50。
  • 限制：K 是固定的，不會隨分布形狀調整。分布很尖時可能放進差的候選，分布很平時又可能砍掉合理選項。

Top-p（nucleus）抽樣

  • 不固定個數，而是選出累積機率剛好達到門檻 p 的最小一組高機率詞，再從中抽樣。
  • 候選數量每一步都會自動調整：示範中 p 為 0.92 時，第一步需要 9 個詞，第二步只需要 3 個。
  • Top-K 與 top-p 可以一起使用。

結論

  • 對開放式生成，top-p 與 top-K 抽樣通常比 greedy 與 beam search 產生更流暢的文字。
  • 沒有一種方法適合所有情況，要依用途選擇。
